# TradeLab Cloud V6.1 — MCX Auto-Debate and monitoring

## Base and scope
Based on the uploaded `papertrade(6).zip`, not the local application. Existing NSE scheduler, agent prompts, database model, deployment files, and broker streaming adapter remain unchanged. The MCX path is intentionally separate; do not change `normalize_index_symbol()` to accept commodities. Source-only archive: no `.env`, private DB, scrip cache, session JSON, Git history, node_modules, build products or bytecode. No production connectivity was used. No existing records were edited.

## Implemented source
- `backend/mcx_ai.py`: dedicated Bull/Bear/Judge Gemini JSON prompts, concurrent Bull and Bear with Judge arbitration, no heuristic fallback on agent failure. Five timeframes using existing historical candle service and validated completed bars (50 minimum per available frame); 5m mandatory for debate, other missing frames explicitly UNKNOWN and prevent automatic execution. Exact contract selection, future quote and 5m freshness recheck, independent direction and two-sided option validation, estimated fee-adjusted reward/risk, and strict verdict validation. Actual observed ask entry, tick-rounded price geometry, expiry-day auto-entry block. Missing mapping blocks execution. No predictions guaranteed.
- `backend/mcx_storage.py`: existing AppKVModel JSON store, transaction-scoped PostgreSQL advisory locks including first-row creation, process lock plus BEGIN IMMEDIATE for SQLite tests. All MCX ledger writes use this helper. PostgreSQL runtime verification still required.
- `backend/mcx_market.py`: existing `mcx-paper:<uid>` retained. New `mcx-champion:<uid>` and `mcx-challenger:<uid>` research wallets. Removed 100-closed-trade storage truncation and 50-trade response cap. Prior discarded records cannot be recovered by code; use verified backups if available, do not invent rows. Duplicate fill prevention by debate ID, eligible position IDs for settlement, finite input checks, expiry-day BUY block, overdue status, independent close buffer. Existing premium-based P&L formula and fee estimate retained, not broker-certified. No short orders, futures orders or expiry devolvement implemented.
- `backend/main.py`: authenticated MCX debate run/status/config/history, research summary endpoints. GET state read-only with daily realized summaries. Manual order requires fresh ask; manual square-off requires fresh bid, not LTP. Start and cancel independent MCX scheduler and position monitoring in FastAPI lifespan. Index pathways unchanged.
- `backend/config.py` / `.env.example`: verification gates, explicit expiry-to-futures map, historical calendar ranges, per-trade and daily loss settings.
- `frontend/src/components/McxResearch.jsx`: Option Buy/Sell, Chat, History tabs, existing chart kept mounted, wallet refresh, unresolved exit warning.
- `frontend/src/components/McxDebatePanel.jsx`: manual debate, persistent scheduler start/stop/update, interval/lots/cap including 0 = no count limit, auto execution checkbox gated by backend, next-run timestamp, agent outputs, quant reasons, memory sample sizes, trade dates and daily reports, paged debate history and basic research comparison. Responsive CSS, browser layout unverified.

## Execution and scheduling
Scheduler state stored alongside primary MCX ledger in `ai_config`; debate history in `debates`. Independent scheduler scans enabled accounts in MCX session, persists next run and a 5-minute lease, runs up to two account tasks per process. Debates bounded to 150s; recovery after crash waits for expired lease. Generation checked inside primary wallet transaction to prevent an in-flight debate filling after settings change/stop. The scheduler does not use NSE session state. Manual debate does not place primary trades. Separate monitor scans the three MCX ledgers during MCX session, samples fresh executable bids approximately every 3 seconds plus work latency, closes SL/target or due positions 2 minutes before close and retries on subsequent session if quote available. Positions without executable prices remain unresolved. Render Free may sleep; no guaranteed uninterrupted monitoring; no exchange-level actual fills. Monitor is sampled, not lossless ticks.

Primary auto cap defaults 5 (configurable 0..100); 0 disables count cap only. Max one open primary MCX position, estimated stop risk <= 0.25% current cash and daily realized loss budget 1% (configurable env), 30-minute exact-contract stop-loss cooldown, one-hour pause after 3 consecutive stop-loss exits, no entry within five minutes of closing. Net reward/risk 1.5 and max spread 2% use existing quant rules. Price gaps may exceed estimated risk; no guarantee. Primary actual quote validation also requires calendar/specification and exact mapping confirmation. Research is hypothetical and uses separate wallets, shared debate (Champion original proposal, Challenger direction + option filter), max 20 open positions each, no fixed daily count. It is disabled by default and requires verified mapping/specifications/calendar to open research positions. Not a pair of independent LLM debates. Research may skip opportunities due to lack of a valid price or risk geometry. No live statistical proof of improved performance.

## Memory and reporting
Intraday plus last 5/30/90 distinct completed-trade dates, closed timestamps <= snapshot, measured P&L/wins/loss reasons/sample sizes; separate primary, Champion, Challenger data, only account-specific MCX. Legacy source tags may be absent. Reports are derived on-demand from exit date in IST with fees and outcomes, not scheduled persisted Gemini narratives. No retraining, no claim of causation. Learning currently uses aggregate evidence rather than regime-matched retrieval for MCX. Daily and research statistics retain all accessible historical rows.

Keep production `.env` and existing Supabase URL. New config defaults:
```

MCX_SHADOW_ENABLED=false
MCX_SPECIFICATIONS_VERIFIED=false
MCX_CALENDAR_VERIFIED=false

MCX_HISTORICAL_SESSIONS=

MCX_MAX_DAILY_LOSS_PCT=1.0
```
Verify broker/exchange contract token, actual lot multiplier, tick size, fees and expiry-to-exact-futures mapping. Configure map as JSON with option expiry ISO date key and exact underlying futures symbol value, from verified data only. Current calendar window inherited from previous source (2026-11-02 through 2027-03-12, 09:00–23:55); not independently verified here. Configure official holidays and special sessions, and earlier historical ranges using `start/end/open/close` comma-separated entries. The default window cannot supply 50 daily bars as of Nov 27. Even with calendar history, a particular futures contract may have insufficient bars; leave its frame UNKNOWN, do not splice different contracts as if same instrument. All 5 frames must pass for auto entries. Start Auto-Debate in Chat with auto-execute off first; only enable gate flags and UI after live verification and validated calendar/specifications. Research flag optional, same safety requirements. Do not change NSE auto-execution flags inadvertently.
